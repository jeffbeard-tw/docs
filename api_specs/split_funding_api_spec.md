## Summary

The purpose of this document is to provide our partners with an informative reference to be utilized while successfully integrating with the Split Funding API offered by MerchantE by Omise (ME). This API was designed to enable our partners' businesses to split their daily settlement amount into two different bank accounts.

### Documentation

The PCI Security Standards Council manages the rules that merchants must follow when using payment cards. Those rules are available at: [https://www.pcisecuritystandards.org/](https://www.pcisecuritystandards.org/).

The North American Industry Classification System (NAICS) is used by the United States, Canada, and Mexico to classify businesses by industry. The United States Census Bureau NAICS lookup can be found here: [https://www.census.gov/econ/isp/](https://www.census.gov/econ/isp/).

## Funding Amounts Request

Used to create or modify MerchantFundingAmount for approved, non-PIN-debit, cardholder-debit or cardholder-credit Transactions.

```http
URL: [root]/funding-amounts
HTTP Method: POST
Content Type: application/json
```

### Header Fields

- Authorization: The Authorization field contains the credentials of the client making the request and uses the ```Basic``` HTTP Authentication Scheme. The value in the Authorization field has the following format:

  Basic \[encoded credentials\]

  Where \[encoded credentials\] is constructed as follows:

1. The profileId and profileKey of the Terminal making the request are combined with a colon separating the two values

1. The resulting string is encoded using base-64

1. The resulting encoded string is appended to the literal ```Basic```

### Request Body

The request body contains the parameters of the request in JSON format. The request body consists of one or more Transaction objects, and each transaction object consists of one or more MerchantFundingAmount objects.

#### Transaction

Used to specify an approved, non-PIN-debit, cardholder-debit or cardholder-credit Transaction that has corresponding MerchantFundingAmount(s).

- A Funding Amounts Request can contain 1 to 10,000 Transaction(s).

- A Funding Amounts Request must not contain any debit Transactions that have been settled.

- A Funding Amounts Request that has credit transactions can contain transactions that have been settled.

- A Funding Amounts Request must not contain the same Transaction more than once (i.e. no duplicate Transactions in a Funding Amounts Request).

- The Transactions in a Funding Amounts Request for a debit transaction can be specified by either a retrievalReferenceNumber or a transactionId, but not both.

- The Transactions in a Funding Amounts Request for a credit transaction can only be specified by transactionId.

##### Fields

| **Field** | **Description** | **Max Length** | **Format** |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------ |
| id | A value generated by ME for each authorization request. | 32 | AN |
| retrievalReferenceNumber | A value generated by ME for each new authorization request. | 12 | N |

#### MerchantFundingAmount

Used to specify a Merchant and the amount the Merchant should be funded/debited for a given Transaction.

- A Transaction can contain 1 to 10 MerchantFundingAmount(s).

##### Fields

| **Field** | **Description** | **Max Length** | **Format** |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------- | ------------------------------ |
| merchantId | ME's unique identifier of the Merchant that will be funded the specified amount for the corresponding Transaction. For a given Transaction, merchantId must be unique. | 16 | N |
| amount | The unsigned amount the corresponding Merchant should be funded/debited for the corresponding Transaction. The currency of the amount is implied and is the same as the currency of the corresponding Transaction. The location of the decimal point is implied based on the minor units of the currency of the corresponding Transaction. For example, if the currency of the Transaction is USD, then an amount of "100" is interpreted as 1.00 USD.<br /><br />The sum of all amount(s) of a given MerchantFundingAmount must equal the current authorized amount of the corresponding Transaction if the Transaction has not been captured for settlement, or the settlement amount if the Transaction has been captured but not yet settled. | 9 | N |

## Funding Amounts Response

Each Funding Amounts Request will receive a Funding Amounts Response.

```http
Content Type: application/json
```

### HTTP Status Codes

The following Status Codes will be returned under the specified conditions:

| **Status Code** | **Description** |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400 | If the request body cannot be processed due to issues such as: unsupported content type, malformed body, values exceeding the max field size, values of incorrect data type, too many or not enough records |
| 401 | If the provided profileId is unknown or if the provided profileKey is incorrect for the provided profileId |
| 403 | If the provided profileId and profileKey are known and correct, but if the profileId is associated with a profile that is no longer active (i.e. it is suspended or closed) |
| 500 | If the server encountered an unexpected error and could not process the request |
| 200 | If none of the above conditions were met |

Status Code conditions will be assessed in the order listed above and the Status Code returned will be that of the first condition encountered.

### Response Body

The response body consists of fields that summarize the request, request-level error fields, and zero or many TransactionLevelError objects.

**Note:** When the response contains HTTP Status Code other than 200, a body will *not* be provided in the response.

##### Fields

| **Field** | **Description** | **Max Length** | **Format** |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ | ---------------------------------------- | ------------------------------ |
| transactionCount | The number of Transactions specified in the corresponding request. | 6 | N |
| merchantFundingAmountCount | The number of MerchantFundingAmount(s) specified in the corresponding request. | 7 | N |
| amountsSum | The hash sum of amount(s) for all MerchantFundingAmount(s) specified in the corresponding request. Since the request could contain Transactions in more than one currency, the value of amountsSum should not be interpreted as a Monetary sum of amounts with a single currency. | 15 | N |
| successfulTransactionCount | The number of Transactions specified in the corresponding request that did not contain errors and that were processed successfully. | 6 | N |
| errorCode | Specifies a client error that occurred at the request level.<br /><br />When an error occurs at the request level, the value of successfulTransactionCount will be zero. When no error occurs at the request level, no value for errorCode and errorMessage will be provided in the response.<br /><br />The following errorCode values will be returned under the specified request-level error conditions:<br /><br />- 1: will be returned if both retrievalReferenceNumber and transactionId were provided for a Transaction in the Funding Amounts Request.<br />- 2: will be returned if neither retrievalReferenceNumber nor transactionId were provided for a Transaction in the Funding Amounts Request.<br />- 3: will be returned if duplicate Transactions are specified in the request. | 3 | N |
| errorMessage | A human-readable description of the corresponding errorCode. For a given error code, there is no guarantee of what the corresponding errorMessage will be. Thus, no programming decisions should be made based on this value. | 200 | AN |

#### TransactionLevelError

Specifies an error that occurred at the Transaction level. An error that occurred at Transaction level results in the failure to process all MerchantFundingAmount(s) for the Transaction that contained the error.

##### Fields

| **Field** | **Description** | **Length** | **Format** |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------ |
| transactionId | If a transactionId was provided in the request to specify the Transaction, this field will contain the transactionId of the Transaction that was provided in the request that contains the error; otherwise, no value will be provided in this field. | 32 | AN |
| retrievalReferenceNumber | If a retrievalReferenceNumber was provided in the request to specify the Transaction, this field will contain the retrievalReferenceNumber of the Transaction that was provided in the request that contains the error; otherwise, no value will be provided in this field. | 12 | N |
| *errorCode* (see next table for possible values) | Specifies a client error that occurred at the Transaction level. For each Transaction level error that occurs, the value of successfulTransactionCount will be decremented by one from transactionCount in the corresponding PostFundingAmountsResponse. | 3 | N |
| errorMessage | A human-readable description of the corresponding errorCode. For a given error code, there is no guarantee of what the corresponding errorMessage will be. Thus, no programming decisions should be made based on this value. | 200 | AN |

##### errorCode

The following errorCode values will be returned under the specified Transaction-level error conditions:

| **errorCode** | **Description** |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 100 | If the provided transactionId or retrievalReferenceNumber is unknown to ME or if the corresponding Transaction is not an approved, non-PIN-debit, cardholder-debit or cardholder-credit Transaction that was initiated by the Profile corresponding to the provided profileId. |
| 101 | If the provided transactionId corresponds to a debit Transaction that has already been settled. |
| 102 | If a provided merchantId is unknown to ME or corresponds to a Merchant that is no longer active. |
| 103 | If duplicate merchantId(s) are found in a given MerchantFundingAmount. |
| 104 | If an amount is not greater than zero. |
| 105 | If the sum of all amount(s) of a given MerchantFundingAmount does not equal the current authorized amount (when the corresponding Transaction has not yet been captured for settlement) or the settlement amount (when the corresponding Transaction has been captured but not settled). |

errorCode conditions will be assessed in the order listed above and the errorCode returned will be that of the first condition encountered.
